**Recommendation:** retain AllMyStuff's application policy and capabilities, and adapt its mesh-facing code behind the existing transport boundary. The current tree already consumes a separate mesh engine; removing everything named `mesh`, `ownership`, or `service` would remove application behavior and authorization. No reviewed MyOwnMesh v1.0.0 API is established by this evidence.

The committed daemon pin is [`v0.3.21`](../../../.myownmesh-rev). The [mobile manifest](../../../gui/mobile/Cargo.toml#L93) pins both `myownmesh` and `myownmesh-core` to that tag, and [its lock](../../../gui/mobile/Cargo.lock#L3244) resolves the dependency to `59143cbdb094b6b99464c224a500e148fd7d2113`. The publicly accessible [v0.3.21 release page](https://github.com/mrjeeves/MyOwnMesh/releases/tag/v0.3.21), checked on the review date, shows the corresponding `59143cb` commit but provides no detailed migration/API contract. This confirms a published pin, not the installed daemon's identity or v1 compatibility. Some [architecture prose](../../../ARCHITECTURE.md#L540) still calls the bundled pin v0.3.3; use manifests, lockfiles, and code when they disagree with that prose.

There are three distinct contracts:

1. **Daemon transport/control:** [`allmystuff-protocol/control.rs`](../../../crates/allmystuff-protocol/src/control.rs#L1) mirrors newline JSON requests, responses, events, and binary media framing. Identity, peer discovery, network configuration, roster operations, channels, and governance requests terminate at MyOwnMesh. Several replies/configs remain `serde_json::Value`; compiling the mirror does not establish upstream schema compatibility.
2. **Application protocol:** [`app.rs`](../../../crates/allmystuff-protocol/src/app.rs#L26) owns AllMyStuff presence, claims, grants, routes, rooms, and storage channels. Its `PROTOCOL_VERSION = 1` is unrelated to a MyOwnMesh v1.0.0 release. [Existing fixtures](../../../contract-fixtures/README.md) primarily protect AllMyStuff/NanoKVM consumer shapes, not a complete daemon compatibility contract.
3. **Local UI/node IPC:** [`node_control.rs`](../../../node/src/node_control.rs#L1) has its own length-prefixed request/event/binary protocol. Desktop [Tauri commands](../../../gui/src-tauri/src/main.rs#L1) drive an external node. Mobile's actual default [engine boot](../../../gui/mobile/src/engine.rs#L1) embeds the daemon and the same node, then calls node dispatch directly. The transport trait in [mobile-core](../../../crates/allmystuff-mobile-core/src/transport.rs#L135) is not proof that the shipping app uses a separate, fully decoupled native mesh adapter.

In the map below, **keep** means application ownership; **adapt** means retain behavior while changing the integration; **eventual-remove** is conditional on a reviewed replacement and compatibility evidence, never an immediate deletion instruction.

The authorization boundary needs these explicit preservation conditions:

- Preserve authenticated sender **and arrival network** until claim policy is checked ([dispatch](../../../node/src/mesh.rs#L4694)). LAN fallback depends on an independent local sighting and excludes CEC ([arrival policy](../../../node/src/mesh.rs#L11622)); a generic connected-peer boolean loses that distinction.
- Preserve local claim-mode/owner checks and durable-write rollback ([atomic acceptance](../../../node/src/ownership.rs#L262)); claim confirmations are tied to pending outbound claims and fleet-key handoff to the recorded owner ([ownership handling](../../../node/src/mesh.rs#L10228)).
- Preserve the actual trust sources: self, recorded owner, locally authored admission records, and cached daemon roster ([runtime check](../../../node/src/mesh.rs#L17333)). The code retains the prior roster on an unreachable daemon or an empty roster response ([refresh](../../../node/src/mesh.rs#L12241)). Therefore the nearby blanket "empty or stale cache denies" comment is not a complete behavioral contract. Cache freshness, eviction and local re-admission policy need explicit review before a future migration, without silently broadening or tightening them in a preparatory refactor.
- Preserve directional share grants, narrower folder grants, CEC admission versus admitted-route checks, and source-media authorization. App control also has command-specific files/folder/relationship gates ([dispatch](../../../node/src/mesh.rs#L9881)); replacing these with one fleet-membership test would change existing authorized behavior.
- Preserve local IPC access-control mechanisms ([socket binding](../../../node/src/node_control.rs#L646)), state-directory semantics, and process ownership. The custom Windows descriptor is applied only when `service_client_sid()` supplies a SID; otherwise default options are used. Unix `chmod(0600)` failure warns and continues. These mechanisms are not proof of owner-only access in every deployment; no live ACL/security audit was performed.

A media-status parser extraction is deferred. Its future compatibility boundary is precise: at the current [probe site](../../../node/src/mesh.rs#L13018), absent/invalid `media_lanes` leaves the current value unchanged; a `u64` value is clamped to 1..255; absent/non-boolean `media_pipes` becomes false when status `data` is present, but no `data` leaves it unchanged. The path currently uses returned `data` without checking `Response.ok`, and partial subscription failure retains prior success flags. A refactor must not silently change these semantics, request ordering, authorization or lifecycle.

A safe staged migration follows these gates:

1. **Characterize the current consumer contract.** Preserve the pin, record representative daemon replies/errors and feature negotiation, and retain application wire fixtures. Establish isolated regression evidence for claims, grants, roster retention/eviction, and media fallback. Correct stale documentation in a separately scoped change. Local serialization tests alone cannot prove a daemon implements the same protocol.
2. **Separate application modules using the current adapter.** Make selected capabilities optional only when imports, transitive native dependencies, advertised capabilities, command dispatch, and startup tasks all follow the selection. Keep the default behavior. Qualify a small headless `serve` path independently of GUI/viewer builds; this review has not proven any target build.
3. **Adopt a reviewed upstream contract in parallel.** Require explicit versions and contracts for identity continuity, authenticated sender/network metadata, governance/eviction/MFA, channels/media framing, errors/backpressure, state directories, and daemon-versus-library lifecycle. Test old/new peers in isolated state roots before changing deployment or persisted fleet state.
4. **Remove proven redundancies last.** Require a documented support floor, migration/rollback procedure and independent checks before removing mirrors, compatibility transports, bootstrap state or daemon packaging. Application permissions and feature behavior remain acceptance criteria.

Open upstream/product decisions: whether v1 offers a stable lightweight client/wire crate; supported library and daemon APIs/platforms; capability negotiation and version policy; identity/credential/state migration; closed-network membership, cache freshness and eviction guarantees; ownership of disabled-network settings and daemon installation/supervision; media channel/backpressure semantics; which app capabilities belong in the default versus minimal `serve` profile.
