**Verified dependency and cfg issues.** Manifest/code evidence establishes mandatory edges; lock entries alone do not prove a package is compiled for a selected target or feature set.

1. **Native receive codecs survive host exclusion by design.** `node/Cargo.toml:180-196` makes OpenH264, Opus and pixels unconditional. `video_decode.rs:339-449` uses OpenH264 without host; `mesh.rs:473,5796` uses Opus without audio-io. Locked edges are OpenH264 0.9.3 -> openh264-sys2 0.9.6 -> cc/nasm-rs, and Opus 0.3.1 -> audiopus_sys 0.2.2 -> cmake/pkg-config. A manifest-only removal would break real receive paths. A later media-free profile must gate state, dispatch and advertised capability behavior as well as imports.
2. **Windows capture leaks across the existing host boundary.** `node/src/lib.rs:178` always declares win_capture; `win_capture.rs:23` gates only on Windows, and its CPU capture path calls pixels at line 625. Only its GPU portion is host-gated. `node/Cargo.toml:225-254` also enables Direct3D/DXGI/MediaFoundation groups without host. Pixels has no other executable uses outside host video and Windows capture in this repository. The default behavior can stay intact while this opt-out is corrected.
3. **Other mandatory services are genuine closure, not GUI contamination.** Node always declares files/fleetfiles/drive_mount/kvm_media/sites/updater paths. Fleetfiles uses rusqlite (`fleetfiles.rs:18`), which enables bundled SQLite; drive_mount uses dav-server (`drive_mount.rs:20-34`), and KVM media uses tokio-tungstenite (`kvm_media.rs:18`). Node's lock has no Tauri/Wry package. The current architecture separates webview dependencies from the daemon but does not separate application planes within it.
4. **Disabled implementation and advertisement can disagree.** `Mesh::advertised_capabilities` removes only screen/camera when host is off (`mesh.rs:13576-13584`). The bridge still creates input-control/clipboard/system-audio and scanned microphone/speaker capabilities (`crates/allmystuff-bridge/src/lib.rs:95-187`), while the corresponding no-host/no-audio stubs drop operations or emit no frames. Terminal/camera/clipboard-receipt feature tags are separately host-gated (`mesh.rs:4046`). Any finer feature split needs explicit capability/dispatch acceptance criteria; root CLI inventory output is not an engine feature test.
5. **Some flags control runtime defaults, not dependency removal.** `field-telemetry = []` changes `cfg!` inside `telemetry_enabled` (`telemetry.rs:145-149`), but the Windows module and Performance APIs compile either way; runtime opt-in is intentionally retained. `hwenc` is described for Linux/macOS but its dependency/module are not target restricted. Windows `--all-features` therefore requests FFmpeg too. Do not claim that defaults-off or flags alone eliminate every platform dependency.

**Build scripts, locks and target limits.** Node's build script only emits target/pin values from `.myownmesh-rev`. Desktop's build script can inspect a sibling daemon, stage binaries, download a release or invoke cargo install; compile-only checks must use its existing `ALLMYSTUFF_SKIP_SIDECAR=1` path (`gui/src-tauri/build.rs:31-59,124`). This does not turn off Tauri/native dependencies or validate runnable sidecars. Mobile always runs tauri-build. Root `.cargo/config.toml` supplies the documented CMake policy floor for native codec builds; builds should run from the worktree root so that configuration applies.
